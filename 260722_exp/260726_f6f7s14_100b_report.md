# F6 / F7 / S14 재작성 — paper-matched gdn2-1.3B (100B 체크포인트) (2026-07-26)

이전 F6/F7/S14는 **checkpoint-10B**(10B 토큰)로 돌렸는데, 10B는 paper-matched **100B**와 상당히
다르므로(95B는 100B와 근사) **model-100b.pth로 재실행**했다. 커널 intercept로 a_t=exp(g)를 직접
캡처(속성 스크래핑 아님)하고, 로컬 SLURM(gpu01, RTX PRO 6000 Blackwell)에서 실행했다.

## 세팅
- 모델: **gdn2-1.3B, model-100b.pth** (`LLM-OS-Models2/gdn2-1.3b-paper-matched`, 17.4GB,
  sha256[:16]=4b03319fbe317ed5). `Config.from_name("gdn2_1.3B")` + `load_state_dict(strict=False)`
  → missing=0 unexpected=0. n_layer=18 × 16 heads, head_dim(cap)=128. bf16, fused_recurrent.
- a_t 캡처: **kernel-intercept** — `lit_gpt.gdn2.fused_recurrent_gdn2`를 monkeypatch해 `g` 인자를 직접
  stash (use_gate_in_kernel=False → g=log-decay, a_t=exp(g)). F7 개입도 이 커널 입력으로 재실행.
- 입력: 자연어 문단(F6/F7), 데이터유형 4종(S14). layers=[2,5,8,10,13,16].
- 실행: 로컬 SLURM `sbatch`(로그인 노드 cuInit=100 → compute 노드 필수), venv torch 2.13+cu130,
  vendored fla 0.5.2, dscpkg lit_gpt. mamba-ssm 불필요(gdn2 전용).
- 코드/산출물: `260722_exp/rank_decomp_100b.py`, `run_f6f7s14.sbatch`, `260726_f6f7s14_100b/`(PNG·npy).

## 결과 (보수적, 실측)

### F7 — decay vs 뭉침 분해 (headline)
| 조건 | eRank | |
|---|---|---|
| real g, real k | **17.14** | 실제 state (cap 128 → **~87% idle**) |
| g=1, real k | 55.18 | **+decay 38.04** |
| real g, iso k(norm-matched) | 25.27 | **+aniso 8.13** |
| g=1, iso k | 55.98 | interaction −7.33 |

→ **decay:뭉침 ≈ 4.7 : 1.** decay가 압도적 주원인, 뭉침은 부차. **10B(real 20.1, +decay 43.7,
+aniso 9.9, 비율 4.4:1)와 방향·크기 모두 일치** — paper-matched 100B에서도 결론 유지, 오히려 약간 강함.

### F6 — head별 decay(r̄) vs eRank
- eRank 범위 **2.2 ~ 50.3 / 128** (head마다 넓게 분포), 이론곡선 e/(1−r̄)의 상승 추세를 따름.
- (10B: 3.4~56.5). 유사한 분포.

### S14 — 데이터유형별 eRank 궤적 (multi-seq ±band)
- 최종 eRank: natural 14.09 / knowledge 14.08 / code 13.58 / math 13.10 (4 seq/유형).
- **유형 간 분리 여전히 약함(≈13~14, 밴드 겹침)** — 10B와 동일한 정직한 관찰. eRank는 다양 vs 반복은
  가르지만 서로 다른 다양한 유형끼리는 잘 구별하지 못함.

## 객관적 사실 (100B 확정)
1. **낮은 eRank의 주원인 = decay** (real→g=1 +38.0 vs real→iso-k +8.1, 약 4.7배). 뭉침은 실재하나
   부차적. paper-matched 100B에서 확정.
2. real state eRank = **17.1/128 ≈ 87% idle** (10B 84%와 유사).
3. **a_t 캡처는 kernel-intercept로 해결** (fused_recurrent_gdn2의 g 직접 캡처, a_t=exp(g)).
4. 10B→100B로 절대 수치는 조금 낮아졌으나(real 20.1→17.1) **정성적 결론은 불변**.
